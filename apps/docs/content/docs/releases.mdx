Two packages publish publicly to npm from this repo:

| Package | What it ships |
|---|---|
| [`@plainconceptsplatform/ui-theme`](https://www.npmjs.com/package/@plainconceptsplatform/ui-theme) | Design tokens, CSS only |
| [`@plainconceptsplatform/ui-components`](https://www.npmjs.com/package/@plainconceptsplatform/ui-components) | Shared React components |

Both follow semver, with one wrinkle worth stating plainly.

## What counts as a breaking change

A token package breaks things in a way types cannot catch. The version reflects **visual** impact, not just API impact.

| Change | Bump | Why |
|---|---|---|
| Adding a token or a component | minor | Nothing existing moves. |
| Changing a token's **value** | minor | Every consuming app changes appearance on upgrade, but nothing fails to build. Read the changelog before taking it. |
| Removing or renaming a token | major | Utilities and `var()` references stop resolving. |
| Changing a component's props | major | Ordinary API break. |
| Neutralising a whole utility scale (for example shadows) | major | Existing markup silently renders differently. |

<Callout type="warn">
  A minor bump can still change how your app looks. That is the nature of a shared token package: the alternative is calling every palette adjustment a major, which would stop anyone from upgrading. Check the changelog for a "visual change" note.
</Callout>

## Taking an update

```bash
pnpm up @plainconceptsplatform/ui-theme @plainconceptsplatform/ui-components
```

Then look at the app in both light and dark before merging. Token changes are exactly the kind of thing that looks fine in one mode and wrong in the other.

Never fork the theme in an app to avoid an upgrade. If an update is wrong for you, that is a bug worth [reporting](https://github.com/PlainConceptsPlatform/Foundations/issues), because it is probably wrong for the other apps too.

## How a release happens

The pull request that changes a package also bumps its `version` and adds the changelog entry, so the version and the reason for it are reviewed together. After it merges, a maintainer publishes from a clean `main`:

```bash
pnpm release:theme        # @plainconceptsplatform/ui-theme
pnpm release:components   # @plainconceptsplatform/ui-components
```

Each script builds the components, typechecks the workspace and publishes that one package to npm. No workflow publishes and there is no release pull request to merge. See [Contributing](/docs/contributing) for the contributor side.

## Deprecation

Deprecated tokens and components keep working for at least one minor release, with the replacement named in the changelog. Removal is a major bump. If a deprecation window would be genuinely painful for an app, say so on the pull request rather than pinning an old version.
