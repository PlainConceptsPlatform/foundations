# Project Guardrails

> Auto-generated by `/make-guardrails`. Regenerate with the same command when architecture or conventions change.

## Architecture Constraints

- Never import from a layer above the current one in the FSD dependency direction (app → views → widgets → features → entities → shared); siblings do not import each other either — compose them one layer up. Nothing in Biome or tsc catches a cross-layer import.
- Never deep-reach into a slice's internals (`features/user/components/Profile`); import only through its `index.ts` barrel, or a refactor inside the slice silently breaks consumers.
- Never register or resolve inversify bindings inside `entities/` or domain code; the container belongs in the composition root under `app/`, resolved in `views`/`widgets`/`features`. Nothing enforces this boundary.
- Never enable `experimentalDecorators` in tsconfig alone for an app using inversify; the SWC/Babel compiler must also enable decorators, or they type-check but throw at runtime.
- Never add `widgets/`, `features/`, or `entities/` layers preemptively; a new app starts with `app/`, `views/`, `shared/`, and a layer appears only when a real need exists.
- Never throw exceptions for domain errors in .NET; use the `ErrorOr` result pattern so the middleware maps to RFC 7807 ProblemDetails. A thrown domain error is not a control-flow failure.
- Never add a `docker-compose.yml` alongside Aspire; the AppHost is the only composition root and a compose file drifts from it.
- Never add .NET modules, layers, or a mediator preemptively; introduce them only when a real boundary demands it.

## File Organization

- Never wrap a third-party component "just in case"; use shadcn/ui and the ARCHITECTURE.md libraries directly. A wrapper with no added behaviour is a maintenance surface with no benefit.
- Never promote a component to `@plainconceptsplatform/ui-components` before the same real requirement appears in multiple apps; the shared layer owns tokens and conventions, not a component catalog.

## Naming Conventions

- Never name a slice folder as a grab-bag (`utils`, `helpers`, `common`); use singular domain nouns, or the slice has no boundary and grows unbounded.
- Never name files or folders in anything but `kebab-case`; React component exports are `PascalCase` and hooks are `useX`. Biome does not check file naming, so violations are silent.

## Code Style

- Never transition `width`, `height`, `top`/`left`, or `box-shadow` in CSS; they force layout or paint on every frame. Transition only `color`, `background-color`, `border-color`, `opacity`, and `transform`.
- Never use `shadow-*` classes for elevation; the theme overrides the Tailwind shadow scale to transparent so they compile but paint nothing. Elevation is `border-border` with `bg-card`.
- Never use `--accent` or other tint tokens as a chart series colour; they are hover surfaces and disappear against a card. Use `--chart-1` through `--chart-5`.
- Never hardcode raw hex or pixel values; use semantic theme tokens (`bg-primary`, `text-muted-foreground`, `rounded-lg`), or the value drifts from the theme.
- Never omit loading (skeletons), empty, error, or success states for any data-driven screen; Biome and tsc do not check for missing states, and a happy-path-only screen ships broken.
- Never rely on Biome's a11y ruleset alone for accessibility; meet WCAG 2.2 AA contrast and honour `prefers-reduced-motion: reduce` by dropping to no transition, which Biome does not check.

## Data & State

- Never hand-edit the token tables in `ai/DESIGN.md`; `packages/theme/src/theme.css` is the source of truth, and the tables mirror it. Edit `theme.css` and regenerate.
- Never restate a fact (stack table, token value, convention) in a docs narrative page when it already lives in the reference; link to it instead, or the two drift and one goes stale.

## Security

- Never attach a self-hosted runner to a public repository; it is a security boundary, and nothing in the workflow config prevents it.
- Never block crawling (`/robots.txt` Disallow-all) before `X-Robots-Tag: noindex, nofollow` has been live long enough for crawlers to read it; an already-indexed URL stays indexed when the crawler never fetches the page.

## Dependencies

- Never use `npm` or `yarn`; the workspace, lockfile, and CI are pnpm-specific, and another manager corrupts the lockfile or misses workspace links.
- Never put domain-specific data-viz palettes (Special Days, Unit, Area, Teams) in `@plainconceptsplatform/ui-theme`; they live in the app that owns them.

## Build & Deployment

- Never publish `@plainconceptsplatform/ui-theme` or `ui-components` from a laptop; publishing goes through CI after merge to main so provenance is attached. Local `npm publish` bypasses it.
- Never use `GITHUB_TOKEN` for an action that must trigger another workflow; GitHub suppresses events caused by `GITHUB_TOKEN`, so the downstream workflow never starts. Mint a GitHub App token instead.
- Never rely on `set -uo pipefail` to stop early exit in a GitHub Actions step; Actions runs `bash -eo pipefail`, so `-e` stays on. Use `set +e` explicitly before a command whose exit code you capture.
